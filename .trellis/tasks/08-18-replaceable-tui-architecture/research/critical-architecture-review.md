# Critical architecture review

## Confirmed issues

1. **Legacy facade dependency cycle.** A renderer-neutral `e-agent-tui` cannot implement `e_agent_tui::run()` by constructing `e-agent-tui-ratatui` while `e-agent-tui-ratatui` depends on `e-agent-tui`. The “tiny re-export arrangement” does not solve Cargo's cycle. Keep `e-agent-tui` as the legacy facade, introduce a neutral `e-agent-tui-api`, and make both the facade and Ratatui implementation depend on the API.
2. **Renderer replacement type mismatch.** `InteractiveRunner<R>` cannot replace `R` with a different concrete renderer type. The runtime seam must be `Box<dyn Renderer>` plus a factory selected/provided by CLI.
3. **State ownership contradiction.** The renderer was said to own the component tree/focus while the runner must preserve component IDs, overlays, focus, viewport, and contributions. Portable interaction/component state must be runner-owned; renderer suspension should carry only mode-private presentation state.
4. **Undefined component rendering contract.** `RenderContext`, `InputContext`, `Rect`, style behavior, clipping, width, cursor publication, and output ownership were unspecified, so a second renderer could not implement the contract deterministically. Define a concrete renderer-neutral semantic cell buffer and contexts; components write clipped cells and publish effects/cursor through the context.
5. **JS callback/thread contradiction.** A `PiAnsiComponent` cannot synchronously call JS from the renderer thread while closures remain on the dedicated JS thread, and a non-`Send` JS component cannot cross threads. Split it into a JS-thread callback producer that parses ANSI and publishes immutable semantic frames, and a native cached-frame component that never calls JS during `render()`.
6. **Impossible hang isolation claim.** A deadline can stop the UI from waiting, but cannot preempt a synchronous infinite JS callback on a single runtime thread. The frontend/session can remain responsive and disable the contribution; that runtime may remain wedged. Tests must distinguish delayed/rejected callbacks from an isolated child-process infinite-loop test.
7. **Impossible fully atomic terminal swap.** Starting two terminal owners concurrently is unsafe, and after old renderer shutdown a new renderer failure cannot guarantee the old renderer remains usable. Use factory preflight, suspend/stop old, start/resume new, then best-effort rollback; otherwise restore and exit cleanly.
8. **Protocol test mismatch.** “Unknown optional-field tolerance” is not meaningful for typed in-process Rust channels without a serialization format. Keep major-version validation and additive minor-version source compatibility; test unknown operations as typed `UnsupportedOperation`.
9. **Pi 0.84.2 semantic mismatch.** `editor(title, prefill)` has no timeout/AbortSignal options. Timeout/AbortSignal acceptance applies to select/confirm/input. Notifications should preserve pi’s transcript-style interactive presentation. Overlay-close compatibility must pin the 0.84.2 topmost-overlay behavior where the public implementation does so.
10. **Stage 0 contradiction.** It claimed no runtime change while also suggesting splitting the monolith. Stage 0 should add tests/fixtures only.
